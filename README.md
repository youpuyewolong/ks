# 小耳朵 · 故事小屋

单用户故事网站，Node.js 24 + SQLite，无第三方运行依赖。前台专注听故事，后台专注录音和内容管理。

已内置口袋神探第 1～7 季官方目录：7 个专辑、1201 个条目及本地封面。首次启动会自动写入 SQLite，录音均留空，直接在后台对应分集点击「上传录音」即可使用。资料数量与来源见 [catalogs/README.md](catalogs/README.md)。

GitHub 上传、树莓派 Docker 部署、更新和备份操作见 [DEPLOY.md](DEPLOY.md)。`npm start` 会自动读取本机 `.env`（如果存在）。

## 本机运行

```powershell
npm start
```

- 听故事：http://localhost:5173/
- 内容后台：http://localhost:5173/admin
- 验证：`npm run check`、`npm test`

默认只监听本机地址。未配置管理密码时，仅本机可管理；无需为听众创建账号。Node 24 的 SQLite 模块可能显示 ExperimentalWarning，不影响运行。

## 内容管理

后台首页的「从凯叔链接导入」接受 `https://kids.kaishustory.com/h5/ks-detailPage/story?albumId=...` 一类专辑分享链接。粘贴链接、选择新专辑分类，点击「获取并导入」，即可获取专辑名称、简介、封面、完整分集名称/副标题/时长和封面。支持分组目录，下载进度实时展示；完成后点击「管理分集 / 上传录音」。仅获取公开目录与图片，不获取音频。

图片下载到本地并校验后，目录统一写入 SQLite。新专辑默认上架；没有录音的分集显示「录音准备中」。重复导入按官方专辑和分集编号识别，补充新分集、更新封面/副标题/类型，保留已有标题、顺序、分类、简介、上架状态、录音和收听进度。自动分类将口袋神探放入「侦探推理」，其他专辑放入「链接导入」，也可手动选分类。

服务端需能访问官方 API 和图片 CDN，无需安装浏览器或额外依赖。分享链接中的登录及追踪参数不会保存或使用。官方要求登录、接口结构变化、目录数量不符或图片下载失败时显示错误，不写入半份目录，可重试。同一服务一次导入一个专辑，最多 2000 集、图片总计 250 MB、单图 8 MB、任务最长 15 分钟。关闭页面不影响正在执行的任务，重新打开后台可查询；服务重启后须重新提交未完成任务。任务状态仅在当前服务进程保留，已入库内容永久保存。

1. 后台「分类管理」可新增、改名、排序、删除分类。有故事的分类不能直接删除。
2. 新建故事，设置标题、简介、分类。保存后开启分集上传。
3. 已有目录时可逐集点击「上传录音」，文件名任意；批量选择或拖入时先按名称/主线集数匹配，再确认对应关系后上传。不确定、重复或名称与集数冲突时需手动选集；请勿将目录列表的序号当作主线集号。无目录时可选择「新建分集」。支持上传进度和失败重试。
4. 分集可搜索、按待上传/已有录音筛选、修改名称/副标题/类型/封面、上下排序、试听、删除或替换录音。替换会确认并重置该分集进度。单集故事也采用同一结构。
5. 上传 JPG/PNG/WebP 封面并保存；不上传则使用默认插画。勾选「上架」并保存，前台才会展示。目录可以先上架，没有录音的分集显示「录音准备中」。删除最后一个分集会自动下架。

音频支持 MP3/M4A/WAV/OGG/FLAC/AAC，单文件最大 500 MB；封面最大 10 MB。服务端校验文件头并流式写入磁盘。浏览器解码支持因设备而异，建议优先使用 MP3。列表中时长为 00:00 的录音，应先试听确认；成功播放后前台会补录时长。删除故事会删除所属分集、收听记录及不再引用的文件，操作前有确认弹窗。

## 收听

前台只展示已上架专辑，支持分类、搜索、收藏、分集选择、上一集/下一集、拖动进度、前后 15 秒、倍速、音量、连播开关。默认按专辑分集顺序连播，跳过未上传录音的条目，最后一段可听录音结束后停止。支持本集结束停止，以及 15/30/60 分钟定时停止，优先于连播。刷新后需点击「继续收听」，不会自动出声。暂停、切集、页面隐藏及播放过程中定期写入进度。已听完分集续听时进入下一集，整部听完后可从第一集重听。

故事、分类、收藏、各集进度存于 `data/stories.sqlite`；封面与录音存于 `data/media/`。清除浏览器数据不会删除这些内容。所有设备连接同一服务时使用同一份单用户收听记录，界面在加载时获取最新记录；不支持多人独立进度或多设备同时播放协调。连播开关保留在浏览器本地。

早期原型保存在 IndexedDB 的录音不会自动迁移；请在后台重新上传原始录音。内置目录没有附带录音。

## 服务器部署

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '5173'
$env:ADMIN_PASSWORD = '请替换为自己的强管理密码'
node server.js
```

对外监听必须配置 `ADMIN_PASSWORD`，后台通过管理密码建立 HttpOnly 会话，不需要注册。生产环境应使用 HTTPS 反向代理并设置 `COOKIE_SECURE=1`，将代理上传大小设为至少 500 MB，上传超时设为至少 30 分钟。使用进程管理器确保服务自动启动。`DATA_DIR` 可指定持久化数据目录，默认项目下 `data`。

前台按用户要求不设登录，访问地址的人会共享同一份听众进度和收藏。若只希望自己访问，可在局域网或私有网络部署。本仓库目前已本机运行，未部署到公网。

## 备份与恢复

先停止服务，再备份整个 `data` 目录（包含 SQLite 及可能存在的 `-wal` / `-shm` 文件、media 文件夹），不要只备份数据库而漏掉录音。恢复时停止服务并将完整备份放回同一数据目录，再启动。

测试使用独立临时数据库，不改动正式故事库。接口验收覆盖分类与故事管理、草稿访问限制、上传类型校验、分集排序、Range/HEAD 读取、进度持久化和乱序请求保护、收藏、服务重启、管理会话、跨站写入拒绝及文件清理。浏览器已人工验证批量上传自然排序、上架、自动连播、末集停止、刷新恢复指定分集时间、本集结束停止。
